## 2. Detailed Improvement Manifest
| Category | File Target | Identified Defect / Flaw | Applied Fix / Refactor | Impact & Verification |
|---|---|---|---|---|
| Bug | `timer.sh` | `timer.sh` had no root check, but the `net-off.sh` it invokes on expiry requires root and self-terminates via `kill $$` if not root. Per `usage.md`'s documented example (`bash timer.sh 300`, no sudo), a scheduled lockdown would silently do nothing when it fired — the dead-man's-switch's core guarantee would fail without any visible error. | Added a `check_root` gate at the top of `timer.sh`, matching the existing convention in `net-off.sh`/`net-on.sh`, so a non-root invocation fails loudly at scheduling time instead of silently at expiry time. | Verification: `bash -n timer.sh` passes; gate mirrors the already-proven pattern in `net-off.sh`. |
| Correctness Risk | `common.sh` | As a consequence of the fix above, timers now normally run as root. `get_timer_pid()` used `kill -0 "$pid"` alone to detect liveness, which fails with "permission denied" (not "no such process") when a non-root user checks a root-owned PID. `status.sh` is documented to run without sudo, so it would misreport an active root timer as "NOT RUNNING" (desynced state). | Added a `/proc/$pid` existence fallback in `get_timer_pid()` so process liveness is detected correctly regardless of the caller's permission to signal it. | Verification: Logic now treats `kill -0` success OR `/proc/$pid` existing as "running"; `bash -n common.sh` passes. |
| Resilience | `timer.sh` | The `TERM` trap referenced `$SLEEP_PID` before it was guaranteed to be assigned (registered before `sleep ... &`). Under `set -u`, a TERM signal arriving in that narrow window would hit an unbound-variable error inside the trap instead of cleanly killing `sleep`. | Initialized `SLEEP_PID=""` before registering the trap and guarded the trap body with `[[ -n "$SLEEP_PID" ]]`. | Verification: Trap body no longer expands a possibly-unset variable; `bash -n timer.sh` passes. |
| Resilience | `status.sh` | `NM_STATE=$(nmcli networking connectivity check 2>/dev/null || nmcli networking connectivity)` — if both `nmcli` calls returned non-zero (e.g. NetworkManager reporting an error state), the command substitution's failure would abort the entire script under `set -euo pipefail` before the Radio/Timer sections printed. | Added a final `|| echo "unknown"` fallback so the assignment always succeeds and the rest of the status report still renders. | Verification: `bash -n status.sh` passes; assignment can no longer fail. |
| Dead Code | `test_exit.sh` | A two-line, unreferenced leftover artifact (`#!/bin/bash` + `exit 0`) not called by any script, cron job, or documentation — pure debug/scratch residue. | Removed the file. | Verification: `grep -rn "test_exit"` across the repo returns no remaining references. |
| Docs Consistency | `usage.md` | Two stale/incorrect entries: (1) the Timer example (`bash timer.sh 300` / `bash timer-cancel.sh`) omitted `sudo`, which is now required (see above) and was already inconsistent with every other privileged example in the doc; (2) the Safety section still claimed logs live at `$STATE_DIR/log.txt`, a location superseded by a prior audit that moved `LOG_FILE` to `/tmp/lights-off.log`. | Updated the Timer example to use `sudo`, and corrected the log-file path description. Also updated `timer.sh`'s own printed hint ("cancel it with...") to include `sudo`. | Verification: Manual review of `usage.md` and `timer.sh` output strings against actual `common.sh` behavior. |

## 3. Escalations & Breaking Changes (If Any)
- **Proposed Breaking Changes:** `timer.sh` now refuses to start without root (previously it would "start" but silently fail to lock down when it fired). This is a CLI-visible change for any caller that was invoking it without `sudo`, but it converts a dangerous silent no-op into an immediate, loud error, and brings `timer.sh` in line with the root requirement every other privileged script (`net-off.sh`, `net-on.sh`) already enforces. No prior invocation that was actually working is affected.
- **Architectural Recommendations:** Consider giving `net-off.sh`/`net-on.sh` a transactional state marker (e.g. write STATE_DIR only after all saves succeed) so a mid-lockdown crash can't leave `is_off()` reporting "off" with incomplete saved state — out of scope for this pass as a non-trivial structural change.
